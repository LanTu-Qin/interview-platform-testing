## 快速复现

```bash

python mock/mock_interview_api.py
# 地址 http://127.0.0.1:8080

# 2. 测试账号

```

## 靶场声明

`mock/` 下被测服务是**练习用靶场**：按《接口文档》模拟的假后端，数据存内存、重启即重置，特意埋有安全漏洞供测试练习。它不是本人开发的业务系统——**本仓库本人的产出是全部测试侧资产**。

## 资产亮点

- **用例 30+**：正向 / 负向 / 边界值 / 安全性四类设计，编号唯一管理
- **断言三层**：协议层（HTTP 状态码 / Content-Type / 耗时基线，目录级公共断言）→ 结构层（契约校验）→ 业务层（业务码与关键字段）
- **8 步全链场景**：双角色登录 → 创建 → 提交审核 → 教师查待审 → 审核 → 审计日志 → 学生复查，53 条断言；跨接口数据流用变量提取打通，重启清场后 id 漂移仍全绿（可重复执行设计）
- **安全发现**：S1 服务端未校验 JWT 签名（篡改 payload 可伪造角色越权）；S2 水平越权（可收藏他人未公开记录）
- **缺陷管理**：5 张缺陷单 + Excel 双轨映射（BUG-00X ↔ 禅道 #X），生命周期含"设计如此拒绝 → 重新激活"分支，关闭附回归结论

## 已知设计取舍

创建接口（my-records）只做"仅自己可见的录入"；按接口文档 §3.1.5，submit-review 是"提交审核申请（新建待审记录）"，请求体同创建接口、无 id 参数——接口清单中不存在"按 id 送审"的能力。创建与提交流程的数据流脱节定性为**设计取舍（文档=实现一致，非缺陷）**，详见 `test-assets/defect-management-report.md` 第五节。
